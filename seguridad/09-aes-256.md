# AES-256

**AES-256** = *Advanced Encryption Standard* de 256 bits. Uno de los algoritmos de cifrado más
seguros y usados del mundo.

## Cómo funciona

Es un algoritmo de cifrado **simétrico**: utiliza la misma clave tanto para cifrar (bloquear)
como para descifrar (desbloquear).

1. **Texto plano**: introduces el archivo o mensaje original.
2. **La clave (key)**: genera una clave de 256 bits (una secuencia de 1 y 0 muy larga).
3. **La mezcladora (rounds)**: no solo esconde los datos, los "revuelve" matemáticamente.
   Los datos pasan por 14 rondas de sustitución, transposición y mezcla.
4. **Texto cifrado**: caos de caracteres sin sentido para quien no tenga la llave.

## ¿Qué significa "256"?

Que hay **2^256 combinaciones posibles**:

- Es un 1 seguido de unos 77 ceros.
- Más combinaciones que átomos en todo el universo observable.

## ¿Por qué es tan seguro?

Si pudiéramos poner todas las computadoras del mundo a probar, tardarían miles de años para
una sola clave AES-256. Nadie ha logrado romper una clave por fuerza bruta.

## Ventajas

| Ventaja | Detalle |
|---|---|
| **Seguridad militar** | impenetrable con la tecnología actual |
| **Eficiencia y velocidad** | a pesar de ser ultra seguro es muy rápido: la mayoría de dispositivos traen componentes específicos (AES-NI) |
| **Preparado para el futuro** | robusto frente a las computadoras cuánticas (a diferencia de RSA/ECC, cuya seguridad sí se ve amenazada) |

## Simétrico vs asimétrico

```
   SIMÉTRICO (AES)                    ASIMÉTRICO (RSA, ECC)
   ─────────────────────              ─────────────────────────
   1 clave para cifrar y descifrar    clave pública + privada
   muy rápido (GB/s con AES-NI)       lento (KB/s)
   problema: ¿cómo comparto la clave? resuelve el reparto de claves
        │                                      │
        └──────────► TLS usa AMBOS ◄───────────┘
            asimétrico para acordar la clave,
            simétrico para cifrar los datos
```

## Modos de operación

Un cifrador de bloque como AES cifra bloques de 128 bits; el **modo** decide cómo se encadenan.

| Modo | Estado | Notas |
|---|---|---|
| **GCM** | recomendado | cifra **y autentica** (AEAD): detecta manipulación |
| **CBC** | evitar en TLS | necesita IV y padding; origen de BEAST y POODLE |
| **CTR** | válido | convierte AES en cifrador de flujo, sin autenticación |
| **ECB** | nunca | bloques iguales → texto cifrado igual; se ve el patrón |

```
   ECB: patrones visibles          CBC/GCM: cada bloque depende del anterior
   ███░░░███░░░                    ▓▒░█▒▓░█▒▓░▒
   (se adivina la estructura)      (ruido uniforme)
```

> Regla práctica: si puedes elegir, **AES-256-GCM** o **ChaCha20-Poly1305**.

## Dónde se usa AES-256 en el día a día

| Uso | Detalle |
|---|---|
| TLS/HTTPS | cifrado de la sesión (`TLS_AES_256_GCM_SHA384`) |
| Discos | LUKS (Linux), BitLocker (Windows), FileVault (macOS) |
| Ansible Vault | cifra los ficheros de variables con AES-256 |
| Vault / OpenBao | la barrera de cifrado del almacén |
| Kubernetes | *encryption at rest* de los Secrets en etcd |
| Copias de seguridad | restic, borg, duplicity |
| WPA3 / WPA2 | Wi-Fi |

## Cifrar y descifrar a mano

```bash
# cifrar un fichero con AES-256-GCM derivando clave de una contraseña
openssl enc -aes-256-gcm -pbkdf2 -iter 600000 -salt \
  -in secreto.txt -out secreto.enc

# descifrar
openssl enc -d -aes-256-gcm -pbkdf2 -iter 600000 \
  -in secreto.enc -out secreto.txt

# con Ansible
ansible-vault encrypt vars/produccion.yml
```

## Lo que AES no resuelve

```
   AES protege los DATOS.
   No protege:
     · la gestión de la clave  ← el punto débil real
     · la integridad, si usas un modo sin autenticación
     · los metadatos (tamaño, momento, con quién hablas)
     · una contraseña débil de la que se derive la clave
```

> El ataque práctico casi nunca es contra el algoritmo: es contra la clave mal guardada,
> el backup sin cifrar o la contraseña de 8 caracteres. De ahí que exista Vault/OpenBao.

## Nota sobre computación cuántica

- **AES (simétrico)**: el algoritmo de Grover reduce la seguridad efectiva de AES-256 a
  ~128 bits. Sigue siendo inviable, así que AES-256 se considera *quantum-resistant*.
- **RSA y ECC (asimétricos)**: el algoritmo de Shor **sí** los rompería. Por eso el trabajo de
  criptografía post-cuántica (ML-KEM/Kyber, ML-DSA/Dilithium) se centra en el intercambio de
  claves y las firmas, no en AES.
